# RH2.0 — Critérios de aceite do Login

Use junto de `SPEC.md`. Estes critérios são uma adaptação proposta para RH2.0; não substituem os documentos oficiais dos gestores.

- [ ] AC-01 Tela de login funcional e alinhada ao design existente.
- [ ] AC-02 Teclado, foco visível e mensagens acessíveis.
- [ ] AC-03 Layout responsivo.
- [ ] AC-04 Validação no frontend e backend.
- [ ] AC-05 Login válido cria sessão segura.
- [ ] AC-06 Falha apresenta mensagem genérica.
- [ ] AC-07 Rate limit testado.
- [ ] AC-08 Senhas nunca armazenadas em texto puro.
- [ ] AC-09 Cookie e sessão seguem política documentada.
- [ ] AC-10 Sessão válida sobrevive ao refresh.
- [ ] AC-11 Endpoints privados bloqueiam usuários anônimos.
- [ ] AC-12 Logout invalida sessão no servidor.
- [ ] AC-13 CSRF/Origin verificado conforme arquitetura.
- [ ] AC-14 Build/lint/typecheck executados.
- [ ] AC-15 Testes automatizados executados e resultados registrados.
- [ ] AC-16 Documentação de configuração e execução atualizada.

## Evidências obrigatórias
Para cada critério, informar: teste/ação executada, resultado observado, arquivo/relatório ou captura pertinente e status (passou/falhou/não executado). Não marcar como passou sem evidência.
